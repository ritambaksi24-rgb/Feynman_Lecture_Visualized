# 26 — Accessibility and Scientific UX

## Baseline

The product targets WCAG 2.2 AA for product UI, with capability-specific scientific interaction review.

## Interaction

Primary workflows are keyboard operable.

Direct manipulation has a non-drag alternative when essential.

## Motion

Nonessential motion can be reduced or disabled. Essential scientific meaning remains understandable without animation.

## Color

Scientific meaning does not rely only on color where a practical non-color encoding exists.

Light and Dark themes preserve meaning and contrast.

## Mathematical and scientific accessibility

Equations provide accessible text/semantic descriptions where supported. Important scientific values, units, labels, and explanations are available when visual interpretation alone is insufficient.

## State

Controls expose appropriate focus, selected, pressed, disabled, loading, and error states. Hover is never the only path to essential information.

## Responsive behavior

Scientific workspaces reflow without silently clipping essential controls or labels.

## Progressive disclosure

Advanced controls appear when relevant rather than overwhelming every idea.

## Scientific UX rule

Every control should identify what changes, its valid range, what the change means physically, and which outputs are affected.

## Validation

Use automated checks plus keyboard, reduced-motion, screen-reader, and manual visual review where appropriate.
